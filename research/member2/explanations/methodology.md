# MatchPulse AI — Member 2 / Step 5: Expected AI Explanations

## Purpose
This is a **gold/reference set** of 20 explanations: 5 real StatsBomb passes × 2 audiences × 2 languages. They are authored reference answers, **not outputs actually generated by an LLM**.

## Data provenance
- StatsBomb Open Data: match ID **3788741**, Turkey vs Italy.
- Reference facts: Step 4 `expected_agent_facts.json`, rechecked against original `3788741_events.json`.
- Event IDs link every explanation to the original match records.
- Pass success means a StatsBomb `Pass` event with no `pass.outcome` recorded (the specified project convention).
- `forward_progression = pass.end_location[0] - location[0]` in StatsBomb coordinate units, **not metres**.

## Agent responsibilities
1. **Match Intelligence:** output source-backed structured facts, identifiers, coordinates, and calculations.
2. **Tactical Explainer:** produce proposed descriptions using only these facts, distinguishing observation from interpretation.
3. **Trust & Personalization:** check every claim and evidence reference, then adapt length and vocabulary to `fan`/`analyst`, and wording to `en`/`fr` while retaining identical facts.

## Important safety/accuracy constraints
- All five passes have matched 360 snapshots, but **none has a scientifically confirmed line-breaking classification** here.
- Absence of `under_pressure` is **not evidence of zero pressure**. Do not say 'under high pressure'.
- Only the Jorginho → Berardi pass at **44:32** has the verified `pass.assisted_shot_id` link to an **off-target** shot in this set. Do not project that outcome to the other four passes.
- A forward pass does not independently establish the number of defenders or lines bypassed.
- Do not express StatsBomb coordinate distance/progression in physical metres.

## Review criteria
- **Fact fidelity:** passer, recipient, time, completion and linked shot are exactly aligned with source data.
- **Metric fidelity:** any numeric values match source coordinates with the agreed rounding.
- **Cross-mode consistency:** fan explanations simplify wording but never change facts.
- **Cross-language consistency:** French expresses the same evidence without strengthening claims.
- **Uncertainty handling:** line-breaking and pressure remain unverified, not false.

## Data format
`expected_explanations.json` contains all 20 references, each with `event_id`, `audience`, `language`, `text`, `evidence`, `validation_status` and `prohibited_inferences`.
`explanations_review.csv` is suitable for team review.

## Recommended acceptance procedure
1. Member 1 selects the same event for all four variants.
2. Ask the workflow for fan/en, fan/fr, analyst/en, analyst/fr.
3. Compare identity, outcome, numeric values and evidence; do not require exact wording matches.
4. Inject one unsupported claim ('broke two lines') and verify Agent 3 flags/removes it.
5. Check that switching language/mode does not reprocess or double-count the event.
